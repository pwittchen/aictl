AICTL · v0.46.0 · Rust · HTTP LLM proxy · OpenAI-compatible

server

An HTTP LLM proxy with built-in redaction, prompt-injection blocking, logs, and a per-process audit trail. Point any OpenAI SDK at it to call Anthropic, Gemini, Grok, Mistral, DeepSeek, Kimi, Z.ai, Ollama, GGUF, or MLX models — one endpoint, one master key.

$ curl -fsSL https://aictl.app/server/install.sh | sh

// install

One liner

macOS arm64/x86_64 and Linux x86_64/arm64 ship as prebuilt binaries. The installer detects your platform, downloads the matching artifact from the latest GitHub release, and drops it on $PATH. Unsupported platforms fall back to cargo install.

$ curl -fsSL https://aictl.app/server/install.sh | sh

First launch

On first launch the server generates a 32-byte master API key, persists it to ~/.aictl/config as AICTL_SERVER_MASTER_KEY, and prints it once to stderr. Copy it — every authenticated request needs Authorization: Bearer <key>.

Shared config

The server reads the same ~/.aictl/config the CLI reads. Provider keys, redaction rules, and the prompt-injection guard are tuned once and apply to both surfaces.

// quickstart

Send your first request

Start the server, point an OpenAI SDK at it, send a request. The model id picks the upstream provider — Anthropic, Gemini, Grok, Mistral, DeepSeek, Kimi, Z.ai, Ollama, GGUF, or MLX.

$ aictl-server

If you have the CLI installed, aictl --serve is a convenience shortcut that locates the sibling aictl-server binary and runs it. Trailing args forward verbatim, e.g. aictl --serve -- --bind 0.0.0.0:7878 --quiet.

# Python — point the OpenAI SDK at the proxy. from openai import OpenAI client = OpenAI( api_key="<AICTL_SERVER_MASTER_KEY>", base_url="http://127.0.0.1:7878/v1", ) reply = client.chat.completions.create( model="claude-sonnet-4-6", messages=[{"role": "user", "content": "Hello"}], ) print(reply.choices[0].message.content)
# Plain curl — same endpoint, same master key, any provider. curl http://127.0.0.1:7878/v1/chat/completions \ -H "Authorization: Bearer $AICTL_SERVER_MASTER_KEY" \ -H "Content-Type: application/json" \ -d '{ "model": "gpt-4o-mini", "messages": [{"role": "user", "content": "Hello"}] }'
// claude code

Use it with Claude Code

Claude Code speaks the native Anthropic API. Point its ANTHROPIC_BASE_URL at this server and every prompt routes through aictl-server — tool use, content blocks, prompt caching, and streaming all pass through unchanged, gated on your master key.

# Point Claude Code at aictl-server. export ANTHROPIC_BASE_URL="http://127.0.0.1:7878" export ANTHROPIC_AUTH_TOKEN="$AICTL_SERVER_MASTER_KEY" export ANTHROPIC_MODEL="claude-sonnet-4-6" export ANTHROPIC_SMALL_FAST_MODEL="claude-haiku-4-5-20251001" claude

Three things must already be true on the server host: aictl-server is running, LLM_ANTHROPIC_API_KEY is configured in ~/.aictl/config, and the value of ANTHROPIC_AUTH_TOKEN matches the server's AICTL_SERVER_MASTER_KEY.

Why ANTHROPIC_AUTH_TOKEN

Not ANTHROPIC_API_KEY. Claude Code sends the auth-token form as Authorization: Bearer …, which is what the server's master-key gate reads. The api-key form goes out as x-api-key and never reaches the gate — every request would land as 401.

What routing buys you

The real LLM_ANTHROPIC_API_KEY stays on the server host. Every Claude Code dispatch lands in the audit log as gateway:anthropic, runs through the redactor and prompt-injection guard, and obeys the concurrency cap and per-IP rate limit.

Anthropic models work best

Claude models hit the byte-for-byte passthrough path — prompt caching (up to 90% input-token discount on cached prefixes), extended thinking, fine-grained tool streaming, anthropic-beta features, and PDF content blocks all survive unchanged. Long Claude Code sessions stay cheap and the SSE event timing matches native Anthropic exactly.

Cross-provider routing

Set AICTL_SERVER_MESSAGES_CROSS_PROVIDER=true and Claude Code can run against OpenAI, Gemini, Ollama, Grok, Mistral, DeepSeek, Kimi, or Z.ai — pick the model by setting ANTHROPIC_MODEL to any id from GET /v1/models. Native tool use, content blocks, and streaming all translate through. Anthropic models keep the passthrough path either way.

Trade-offs on non-Anthropic routes

Cross-provider routes lose Anthropic-only features: prompt caching (full input-token cost every turn), extended thinking, fine-grained tool streaming, and any anthropic-beta features. PDF blocks are rejected; cache_control markers are stripped; stop reasons map best-effort. Local GGUF / MLX backends are out of scope — use Ollama with a tool-capable model for local + tools.

// cross-provider

Route Claude Code to any model

Flip AICTL_SERVER_MESSAGES_CROSS_PROVIDER=true and POST /v1/messages stops being a pure Anthropic passthrough — it becomes a bidirectional translator. Claude Code sends its native Anthropic shape; the server rewrites it into OpenAI / Gemini / Ollama / Grok / Mistral / DeepSeek / Kimi / Z.ai shapes, dispatches, then translates the response back. Anthropic models keep the byte-for-byte passthrough path — zero behavioral drift, all Anthropic-only features intact. The flag defaults to off so existing deployments see no change until you opt in.

Experimental. The translator works for most chat-tuned models in the supported families, but it is best-effort — not every model survives the round-trip. Known gaps: OpenAI reasoning models (o1, o3, o3-mini, gpt-5) reject the request shape; Ollama models without the tools capability silently drop tool calls; vision inputs need a vision-capable target model; deepseek-reasoner ignores tools; Anthropic-only tools (memory, computer_use, code_execution_*) have no equivalent on other providers. Upstream rejections surface as 503 provider_unavailable or 400 with the body logged at warn level. Use Anthropic models for production reliability; treat cross-provider routes as best-effort.

# Server host — enable the translator. Make sure the upstream key for # the target provider is configured (LLM_OPENAI_API_KEY, LLM_GEMINI_API_KEY, # …); local Ollama needs no key. export AICTL_SERVER_MESSAGES_CROSS_PROVIDER="true" # Optional — restrict which providers the translator will dispatch to. # export AICTL_SERVER_MESSAGES_TRANSLATE_PROVIDERS="openai,gemini" # Optional — reject instead of stripping unsupported Anthropic-only fields. # export AICTL_SERVER_MESSAGES_FEATURE_GATE="reject" aictl-server
# Client laptop — same Authorization scheme as the Anthropic passthrough; # only the model id changes. Any model from GET /v1/models works. export ANTHROPIC_BASE_URL="http://127.0.0.1:7878" export ANTHROPIC_AUTH_TOKEN="$AICTL_SERVER_MASTER_KEY" export ANTHROPIC_MODEL="gpt-4o-mini" # OpenAI # export ANTHROPIC_MODEL="gemini-2.5-flash" # Gemini # export ANTHROPIC_MODEL="qwen2.5-coder:14b" # Ollama (tool-capable model) # export ANTHROPIC_MODEL="deepseek-chat" # DeepSeek # export ANTHROPIC_MODEL="grok-2-1212" # Grok # export ANTHROPIC_MODEL="mistral-large-latest" # Mistral # export ANTHROPIC_MODEL="kimi-k2-0905-preview" # Kimi # export ANTHROPIC_MODEL="glm-4.6" # Z.ai export ANTHROPIC_SMALL_FAST_MODEL="$ANTHROPIC_MODEL" claude

What you gain

Claude Code (and any other native-Anthropic client) can run against any model the server already supports for /v1/chat/completions. Native tool use, content blocks, image inputs, and streaming all translate. The full mapping table — every Anthropic field across every provider — lives in docs/SERVER.md.

What you give up

On cross-provider routes you lose Anthropic-only features: prompt caching (full input-token cost every turn), extended thinking, fine-grained tool streaming, anthropic-beta features, and native PDF blocks. cache_control markers are stripped; stop reasons map best-effort. Long Claude Code sessions can cost meaningfully more without caching — budget before enabling.

What stays the same

Every request — passthrough or translated — passes the master-key gate, the prompt-injection guard, the redactor on every text surface, and the per-request audit log entry. The concurrency cap and per-IP rate limit apply equally. Translation never relaxes a security pass.

Local-only scope

Ollama is in scope (with a tool-capable model like Qwen 2.5, Llama 3.1+, or Mistral Nemo). GGUF and MLX are rejected on the cross-provider path — the in-process backends don't expose native tool calling. Reasoning models (OpenAI o1, o3) are also not mapped; use /v1/chat/completions for those.

// docker

Run in a container

A multi-stage Dockerfile (Rust → debian:bookworm-slim) lives at docker/server.Dockerfile. Build it, run it with a named volume so the auto-generated master key survives restarts.

# Build from the repo root. docker build -f docker/server.Dockerfile -t aictl-server .
# Persistent named volume holds ~/.aictl/ for the in-container user. docker run --rm -d \ --name aictl-server \ -p 127.0.0.1:7878:7878 \ -v aictl-data:/home/aictl/.aictl \ aictl-server # First launch prints the master key to stderr — capture it. docker logs aictl-server

What's baked in

AICTL_SERVER_BIND defaults to 0.0.0.0:7878 inside the container so the published port is reachable; the master-key gate, body cap, concurrency cap, and optional rate limit still apply. A HEALTHCHECK hits /healthz every 30 s.

Optional features

The gguf and redaction-ner cargo features are off by default — pass --build-arg FEATURES="redaction-ner" to opt in. MLX is Apple-Silicon-only and is never built in the Linux image.

Provider keys

Either bake them into the persisted volume's ~/.aictl/config (one-time, then they roll with restarts) or pass them at run time via -e LLM_OPENAI_API_KEY=…. The CLI's /keys lock flow doesn't apply inside the container — there's no Secret Service to migrate into, so the keyring backend silently falls back to plain config.

TLS

The server itself does not speak TLS. Run nginx, Caddy, or your platform's load balancer in front to terminate HTTPS; the SSE streaming path needs proxy_buffering off on nginx.

// rest api

Endpoints

Seven endpoints. Every authenticated request needs
Authorization: Bearer <master-key>.
GET /healthz and GET /openapi.json are the only auth-free routes.

POST /v1/chat/completions auth required

OpenAI-shaped chat endpoint. The model field picks the provider. stream: true returns SSE in OpenAI's data: {"choices":[{"delta":...}]} shape, ending with data: [DONE].

Request
curl -X POST http://127.0.0.1:7878/v1/chat/completions \ -H "Authorization: Bearer $AICTL_SERVER_MASTER_KEY" \ -H "Content-Type: application/json" \ -d '{ "model": "claude-sonnet-4-6", "messages": [{"role": "user", "content": "Hello"}] }'
Response
{ "id": "chatcmpl-7f3a92...", "object": "chat.completion", "created": 1714411200, "model": "claude-sonnet-4-6", "choices": [{ "index": 0, "message": {"role": "assistant", "content": "Hi!"}, "finish_reason": "stop" }], "usage": {"prompt_tokens": 8, "completion_tokens": 2, "total_tokens": 10} }
POST /v1/messages auth required

Native Anthropic Messages API endpoint — the route Claude Code reaches via ANTHROPIC_BASE_URL. The body is forwarded verbatim to api.anthropic.com/v1/messages with your stored LLM_ANTHROPIC_API_KEY substituted in, so tool use, content blocks, and prompt caching pass through unchanged. stream: true returns the native Anthropic SSE event stream. Non-Anthropic models are rejected with 400 model_not_found.

Request
curl -X POST http://127.0.0.1:7878/v1/messages \ -H "Authorization: Bearer $AICTL_SERVER_MASTER_KEY" \ -H "anthropic-version: 2023-06-01" \ -H "Content-Type: application/json" \ -d '{ "model": "claude-sonnet-4-6", "max_tokens": 1024, "messages": [{"role": "user", "content": "Hello"}] }'
Response
{ "id": "msg_01ABC...", "type": "message", "role": "assistant", "content": [{"type": "text", "text": "Hi!"}], "model": "claude-sonnet-4-6", "stop_reason": "end_turn", "usage": {"input_tokens": 8, "output_tokens": 2} }
POST /v1/completions auth required

Legacy text-completion API. The prompt is wrapped in a single user message and routed through the same provider selection logic.

Request
curl -X POST http://127.0.0.1:7878/v1/completions \ -H "Authorization: Bearer $AICTL_SERVER_MASTER_KEY" \ -H "Content-Type: application/json" \ -d '{ "model": "gpt-4o-mini", "prompt": "Once upon a time" }'
Response
{ "id": "cmpl-3a91...", "object": "text_completion", "created": 1714411200, "model": "gpt-4o-mini", "choices": [{ "index": 0, "text": " in a faraway land...", "finish_reason": "stop" }], "usage": {"prompt_tokens": 5, "completion_tokens": 20, "total_tokens": 25} }
GET /v1/models auth required

Lists every model in the catalogue plus locally available Ollama / GGUF / MLX models, with context_window and an available flag (true when the upstream key is configured).

Request
curl http://127.0.0.1:7878/v1/models \ -H "Authorization: Bearer $AICTL_SERVER_MASTER_KEY"
Response
{ "object": "list", "data": [ { "id": "claude-sonnet-4-6", "object": "model", "owned_by": "Anthropic", "context_window": 200000, "available": true }, { "id": "gpt-4o-mini", "object": "model", "owned_by": "OpenAI", "context_window": 128000, "available": true } ] }
GET /v1/stats auth required

Returns the same usage aggregates the CLI's /stats command shows — today, this month, overall.

Request
curl http://127.0.0.1:7878/v1/stats \ -H "Authorization: Bearer $AICTL_SERVER_MASTER_KEY"
Response
{ "today": { "sessions": 0, "requests": 12, "llm_calls": 12, "tool_calls": 0, "input_tokens": 1840, "output_tokens": 412, "cost_usd": 0.018, "models": {"claude-sonnet-4-6": 8, "gpt-4o-mini": 4} }, "this_month": { /* same shape */ }, "overall": { /* same shape */ } }
GET /healthz public

Liveness probe. Returns status, version, uptime_secs, and active_requests.

Request
curl http://127.0.0.1:7878/healthz
Response
{ "status": "ok", "version": "0.46.0", "uptime_secs": 3812, "active_requests": 0 }
GET /openapi.json public

OpenAPI 3.1 description of every route above — request and response schemas, error envelope, security scheme, status-code table. Point Swagger UI, Redoc, or any SDK generator at it to introspect the surface or generate a typed client. The running server version is embedded under info.version.

Request
curl http://127.0.0.1:7878/openapi.json
Render with Swagger UI
docker run --rm -p 8080:8080 \ -e SWAGGER_JSON_URL=http://host.docker.internal:7878/openapi.json \ swaggerapi/swagger-ui

Every error response is {"error":{"code":"…","message":"…"}} — the same envelope OpenAI uses, so existing SDK error handlers keep working unchanged.

// configuration

Knobs

Every server-only key lives in ~/.aictl/config with the AICTL_SERVER_* prefix. CLI flags override config; config overrides defaults.

AICTL_SERVER_BIND=127.0.0.1:7878 # listen address AICTL_SERVER_MASTER_KEY=<auto-generated> # bearer token AICTL_SERVER_REQUEST_TIMEOUT=120 # per-request seconds; 0 disables AICTL_SERVER_BODY_LIMIT_BYTES=2097152 # 2 MiB AICTL_SERVER_MAX_CONCURRENT_REQUESTS=32 # 503 when saturated AICTL_SERVER_SHUTDOWN_TIMEOUT=20 # SIGTERM drain seconds AICTL_SERVER_SSE_KEEPALIVE=15 # 0 disables AICTL_SERVER_LOG_LEVEL=info # trace|debug|info|warn|error AICTL_SERVER_LOG_FILE=~/.aictl/server.log # empty disables file sink AICTL_SERVER_LOG_BODIES=true # log redacted bodies AICTL_SERVER_CORS_ORIGINS= # empty = CORS off AICTL_SERVER_RATE_LIMIT_RPM=0 # per-IP req/min; 0 disables AICTL_SERVER_RATE_LIMIT_BURST=0 # bucket capacity; 0 = RPM

Server-scoped security flags. Each takes precedence over the matching AICTL_* form when the engine is loaded inside aictl-server; unset overrides fall through to the shared key, so a single-host setup needs no duplication. Tool-dispatch knobs (CWD jail, shell allow/block lists, blocked env vars, disabled tools, max-write byte cap, shell timeout) are intentionally not mirrored — the server does not run tools.

AICTL_SERVER_SECURITY=true # master switch (injection guard + audit); false/0 disables AICTL_SERVER_SECURITY_INJECTION_GUARD=true # run detect_prompt_injection on every user message AICTL_SERVER_SECURITY_AUDIT_LOG=true # gateway:<provider> + redaction events to the audit log AICTL_SERVER_SECURITY_REDACTION=off # off|redact|block (block → 400 redaction_blocked) AICTL_SERVER_SECURITY_REDACTION_LOCAL=false # also redact for local providers (Ollama/GGUF/MLX)

Server-scoped redaction tuning. Same precedence rule as the security flags above — unset server overrides fall through to the matching AICTL_REDACTION_* key. Detector subsetting, custom patterns, allowlists, and the optional Layer-C NER model can be tuned independently for the proxy without forking the CLI's config.

AICTL_SERVER_REDACTION_DETECTORS= # empty = all; subset of api_key,aws,jwt,private_key,connection_string,credit_card,iban,email,phone,url_secret,high_entropy AICTL_SERVER_REDACTION_EXTRA_PATTERNS= # semicolon-separated NAME=REGEX pairs → [REDACTED:NAME] AICTL_SERVER_REDACTION_ALLOW= # semicolon-separated allowlist regexes; matches survive Layer-A/B AICTL_SERVER_REDACTION_NER=false # enable Layer-C NER (requires `redaction-ner` feature + pulled model) AICTL_SERVER_REDACTION_NER_MODEL=onnx-community/gliner_small-v2.1 # NER model spec (owner/repo)
// security

Defense in depth

The same redaction and prompt-injection controls the CLI ships run on every gateway request — same regex bank, same entropy pass, same optional NER, same config.

Master-key gate

Constant-time bearer-token compare. Both wrong-token and missing-token surface as the same 401 body so the distinction can't be enumerated.

Outbound redaction

aictl_core::run::redact_outbound runs on every gateway request. Local providers (Ollama / GGUF / MLX) skip unless AICTL_SECURITY_REDACTION_LOCAL=true.

Prompt-injection guard

Every user message passes through security::detect_prompt_injection. Matches get rejected with 400 prompt_injection so poisoned prompts can't burn the operator's tokens.

Server log

Two sinks share one event source: JSON-Lines appended to ~/.aictl/server.log (override with AICTL_SERVER_LOG_FILE, empty disables) and human-readable lines on stderr. Level via AICTL_SERVER_LOG_LEVEL; rotation is the operator's job. The dedicated audit log sits beside it, recording every gateway dispatch and redaction event.

Rate limit (optional)

Per-client-IP token bucket configurable via AICTL_SERVER_RATE_LIMIT_RPM and AICTL_SERVER_RATE_LIMIT_BURST. Off by default. Saturation returns 429 with a Retry-After header. The global concurrency cap (AICTL_SERVER_MAX_CONCURRENT_REQUESTS) operates independently and remains the primary backpressure mechanism.

Concurrency cap

A global semaphore caps in-flight requests at AICTL_SERVER_MAX_CONCURRENT_REQUESTS (default 32). Saturation returns 503 immediately rather than queueing — clients that care about backpressure handle retry themselves.

// audit log

Every request leaves a trace

One JSON-Lines file per process. Every successful gateway dispatch lands as gateway:<provider> tagged with the per-request UUID; every redaction event lands as its own row. Defaults to ~/.aictl/server-audit.log — one file for the whole process, no session ids (the server has no sessions).

# ~/.aictl/server-audit.log — one JSON object per line. {"timestamp": "2026-05-12T14:22:08Z", "tool": "gateway:anthropic", "input": "Hello", "outcome": "executed", "result_summary": "7f3a92c1abc01234"} {"timestamp": "2026-05-12T14:22:15Z", "event": "redaction", "mode": "redact", "direction": "outbound", "source": "user_message", "matches": [{"kind": "email", "range": [12, 29], "confidence": 1.0, "snippet": "…contact [REDACTED:email] please…"}]} {"timestamp": "2026-05-12T14:22:31Z", "tool": "gateway:openai", "input": "Summarize the diff", "outcome": "executed", "result_summary": "a1b2c3d4e5f60718"}

Where it lives

Default path: ~/.aictl/server-audit.log. Override per launch with --audit-file <PATH>, or persistently with AICTL_SERVER_AUDIT_FILE. Setting the env var to an empty string disables disk audit even when the toggle is on.

What gets recorded

Gateway dispatches — one row per successful upstream call, tagged gateway:openai, gateway:anthropic, …, with the per-request UUID under result_summary so you can correlate with the server log. Redaction events — one row per detection batch, with the kind, character range, confidence, and a placeholder-substituted snippet (the raw secret never lands in the file).

Toggle & rotation

Turn the whole stream off with AICTL_SERVER_SECURITY_AUDIT_LOG=false — every audit::log_* call becomes a no-op. The file is opened append-only; rotation is the operator's job (logrotate, journald, whatever fits the deploy).

Vs the CLI

The CLI keys audit files by session (~/.aictl/audit/<session-id>); the server has no notion of a long-lived session, so one file per process is the whole story. No session id appears anywhere in the rows.
