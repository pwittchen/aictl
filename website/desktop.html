// 01 download

Download & install

macOS 12+ on Apple Silicon and Intel. Signed with a Developer ID and notarized by Apple — opens cleanly on first launch, no Gatekeeper override.

The button hits the latest GitHub release and pulls aictl-desktop-darwin-<arch>.dmg. Open the DMG and drag aictl.app into /Applications.

Apple Silicon build

The aarch64 release ships with native MLX inference enabled and bundles mlx.metallib alongside the binary so on-device models run on the GPU through Metal.

Intel build

The x86_64 release covers Intel Macs. MLX is Apple-Silicon only and is not bundled in this build — every other provider, tool, and feature is identical.

Build from source

The desktop crate is excluded from the workspace's default member set. Build it explicitly with cargo build -p aictl-desktop --features gguf,mlx,redaction-ner, or run the full Tauri dev workflow under crates/aictl-desktop/.

Auto-update

The app verifies a minisign signature on every update before installing — independent of Apple's Developer ID codesign. New builds download, verify, install, and restart in place.

// 02 what you get

One engine, in a window

The desktop app links the same aictl-core Rust crate the CLI uses. No daemon, no sidecar, no second process — the agent loop runs in-process and the webview is just the UI.

Every provider

Eight cloud providers (OpenAI, Anthropic, Gemini, Grok, Mistral, DeepSeek, Kimi, Z.ai), three local backends (Ollama, GGUF, MLX on Apple Silicon), and the aictl-server HTTP proxy — switch mid-session, conversation context stays.

Every tool

All 35 built-in tools work in the desktop app: shell, files, archives, checksums, clipboard, notifications, web fetch, document reading, image vision, code execution, math, JSON / CSV queries, host probes, and long-term memory. Every call passes through the same security policy as the CLI.

Sessions & agents

Persistent sessions in the sidebar, incognito mode, and the same agent / skill catalogue under ~/.aictl/. Resume a session you started in the terminal — or start one here and open it later from the CLI.

MCP, plugins, hooks

Same opt-in extensions as the CLI. Servers declared in ~/.aictl/mcp.json light up in both surfaces; plugins under ~/.aictl/plugins/ dispatch through the same gate; lifecycle hooks fire the same way.

Native chrome

Real macOS window, real menu bar, real keyboard shortcuts. Drag-and-drop a file into the chat to attach it, ⌘K for settings, ⌘N for a new session. No browser tab, no Electron-style memory bloat.

Long-running tasks

Tool calls run in the background while you keep using the rest of the UI. Press Stop on the title bar to cancel any in-flight call and roll back the turn — the same Esc-cancel behavior the CLI ships.

// 03 workspace

Workspace folder

Every tool call — read_file, write_file, exec_shell, list_directory — runs jailed inside a single workspace folder. The pill in the title bar is your current root.

Default location

On first launch the app picks ~/.aictl/workspace/ as the workspace. The folder is created on demand — it is the only directory under ~/.aictl/ that tools can write to. Sibling folders like ~/.aictl/keys and ~/.aictl/audit stay off-limits.

Pick a project

Click the workspace pill to swap to any folder — a project under ~/Code/, a writing project under ~/Documents/, anything reachable from your account. The choice is remembered across launches in AICTL_WORKING_DIR_DESKTOP.

Independent of the CLI

The desktop's workspace is stored separately from the CLI's. Launching the desktop never silently retargets CLI tool calls; the CLI honours AICTL_WORKING_DIR_CLI (or its launch dir) and the desktop honours AICTL_WORKING_DIR_DESKTOP — both surfaces stay coherent.

CWD jail still applies

The workspace is not a hint — it is the jail root. Every shell command and file operation is scoped to it (or rejected). Switch the workspace and the jail moves with it.

// 04 sessions

Sessions sidebar

Every conversation is a session. Persisted as JSON under ~/.aictl/sessions/ and shared with the CLI.

+ NEW

Start a fresh session with an empty context. The previous one stays in the sidebar — click it any time to resume.

INCOGNITO

Spin up a session that is never written to disk. Closes with the window. Use it for one-off prompts that should not appear in your history.

Filter

The filter bar matches against session names and titles. Naming a session is optional — aictl auto-titles each one from the first turn so the sidebar stays readable.

Resume from CLI

A session you started in the terminal with aictl --session shows up in the desktop sidebar on the next launch — same JSON file, same conversation history.

Clear all

One link at the bottom of the sidebar wipes the whole session catalogue. Confirmation dialog first — no surprise deletes.

JSON on disk

Each session is a single JSON file under ~/.aictl/sessions/. Easy to grep from the terminal, easy to back up, easy to inspect — the on-disk shape is the same one the CLI writes.

// 05 chat

Chat & composer

A regular chat surface — user turns, assistant replies, inline tool calls, streaming responses — with a composer pinned to the bottom.

Streaming

Replies stream token by token from every provider that supports it. The Stop button on the title bar cancels mid-stream and rolls back the partial turn so context stays clean.

Markdown rendering

Headings, lists, tables, inline code, and fenced code blocks render as you read. Code blocks have a one-click copy button. Block-level margins are tightened for compact output — reading-long answers without browser-default spacing.

Inline tool calls

Tool invocations appear inline between assistant turns — tool name, arguments, result. The chat reads top-to-bottom like a transcript instead of hiding tool work behind expandable cards.

Model picker

Switch models from the composer footer without opening Settings. The picker pulls from the same catalogue the CLI's /model command uses — cloud providers grouped, local backends grouped, server proxy underneath.

Agents & skills

The two icons next to the model picker open the agent and skill menus. Pick an agent to load a system prompt for the session; pick a skill to drive one turn with a markdown playbook from ~/.aictl/skills/.

Per-turn cost meter

Every assistant turn reports tokens sent, tokens received, estimated cost, and elapsed seconds. Switch from a frontier model to a local one and you see the impact on the next turn — no separate billing dashboard.

// files pane

Workspace files pane

A tree view of the active workspace folder pinned to the right of the chat. Browse, edit, and stage files alongside the conversation — no second window, no external editor required.

Tree view

Every file and directory under the workspace, lazily expanded. Selecting a file opens it in the editor pane; selecting a directory scopes new-file / upload actions to that location.

Create & upload

Create a new file or directory inline, or pull any file from disk into the workspace via the native file picker. Uploads land under the selected directory (or the workspace root) and refuse to clobber an existing entry.

Rename & delete

The pencil icon swaps the row label for an inline input — ↵ commits, Esc cancels even when focus drifts. Destructive actions (delete file, delete directory) route through a single confirm modal styled like the tool-approval prompt.

Editor with syntax highlighting

The editor pane renders a transparent textarea over a highlight.js underlay so cursor position and token colors stay aligned. Language is picked from the file extension, with Dockerfile / Makefile bare-name fallbacks; unknown extensions render as plain text.

Resizable panes

Drag handles between every adjacent pair of visible panes mutate per-pane widths. The chat column absorbs whatever the neighbours give up, so the conversation never gets squeezed into a narrow strip on a wide monitor.

Persistent state

Pane visibility, pane widths, and the last-open file are remembered across launches in dedicated config keys. If the open file disappeared while the app was closed, the files pane forces itself open so you land on something useful instead of a missing editor.

Layout state persists through dedicated keys in ~/.aictl/config: AICTL_DESKTOP_FILES_VISIBLE, AICTL_DESKTOP_OPEN_FILE, AICTL_DESKTOP_SIDEBAR_WIDTH, AICTL_DESKTOP_EDITOR_WIDTH, AICTL_DESKTOP_FILES_WIDTH. All file operations run through the same security policy as read_file / write_file — the workspace is the jail root.

// 06 tool approvals

Tool approvals

By default, the agent asks before running a tool. The approval modal shows you exactly what is about to happen — tool name, arguments, target file or command — and you click Allow, Deny, or Always allow.

Allow once

Run this single call. The next time the agent reaches for the same tool, you are asked again.

Always allow

Pre-approve this tool for the rest of the session. Useful for read-only tools (read_file, list_directory) that you trust the agent with.

Deny

Reject this call and let the agent recover. The model sees a tool error and decides what to do next — usually replan or ask you a clarifying question.

Auto mode

Toggle in Settings to skip every approval prompt. The security policy still applies — this only bypasses the human confirm step. Mirrors the CLI's --auto flag.

Hooks can intercept

PreToolUse hooks can pre-approve or block a tool before the modal even appears. Same JSON-on-stdout protocol as the CLI — configure once in ~/.aictl/hooks.json.

Audit trail

Every tool call — approved, denied, or auto — lands in the per-session JSONL audit log under ~/.aictl/audit/. You can replay exactly what happened in any session.

// 07 settings

Settings panes

⌘K opens the Settings window. Same keys, same providers, same security policy as the CLI — with a graphical editor on top.

Provider & model

Default provider, default model, optional per-task overrides. Changes write through to ~/.aictl/config and take effect immediately — the CLI sees the same change.

API keys

Store, lock, and unlock keys for every supported provider. Keys land in the macOS Keychain via the system Security framework. Plain-config fallback is available for environments without a keychain.

Local models

Curated GGUF and MLX starter lists with one-click downloads. The same catalogue the CLI's /gguf and /mlx menus expose — single source of truth across both surfaces.

Security policy

CWD jail, blocked paths, shell allowlist, environment scrubbing, prompt-injection guard, output sanitization, and credential / PII redaction at the network boundary — every knob that lives in ~/.aictl/config as AICTL_SECURITY_*.

Context

Auto-compact threshold and per-model context limits. The same settings the REPL exposes through /context.

Hooks, MCP, plugins, tools

Browse and toggle every extension. Hooks list shows matchers and timeouts, MCP servers show transport and tool catalogue, plugins show entrypoint and confirmations, tools list shows which are disabled. Same files (~/.aictl/hooks.json, ~/.aictl/mcp.json, ~/.aictl/plugins/) the CLI reads.

// coding agent

Coding agent experimental

Opt-in mode that swaps the general-purpose system prompt for a software-development specialist with an Explore → Plan → Code → Review → Test workflow. Default off — the desktop app stays general-purpose unless you flip it on.

Where to find it

Settings → General → Coding agent is the master switch. There is also a chevrons-in-square icon on the composer toolbar, slotted between the memory and auto-accept toggles, for one-click flipping without leaving the chat.

Same engine underneath

Providers, tools, agents, skills, sessions, audit log, redaction, and the CWD jail are unchanged. Only the base system prompt is swapped — the model is asked to think in Explore → Plan → Code → Review → Test terms before reaching for a tool.

Shared with the CLI

The state lives in ~/.aictl/config as AICTL_CODING_AGENT=true. Flip it in the desktop and the next aictl REPL launches in coding mode — both surfaces read the same config.

Tuning knobs

AICTL_CODING_PLAN_APPROVE, AICTL_CODING_SKIP_REVIEW, AICTL_CODING_SKIP_TEST, AICTL_CODING_TEST_RETRIES, AICTL_CODING_LINTER, and AICTL_CODING_TEST_CMD tune approval gates, phase defaults, and the linter / test commands invoked during Review and Test.

Phase UI is CLI-only in v1

The dim [phase] REPL prefix and the /skip command are terminal-only for now. The desktop benefits from the same prompt steering but does not render an explicit phase tracker yet.

For quick edits, not production

This mode is experimental — best for quick fixes, exploration, and one-off refactors. For production coding work prefer purpose-built tools: Claude Code, OpenAI Codex CLI, or opencode.

// 08 shortcuts

Keyboard shortcuts

A small set of chords for the common flows.

Send

⌘↵ sends the message in the composer. Plain ↵ inserts a newline so multi-line prompts compose without fighting the chat surface.

Settings

⌘K opens the Settings overlay. Hit it again, or press Esc with the panel focused, to close.

Sidebar toggle

⌘\ hides and shows the sessions sidebar — standard macOS pattern, matches Finder and Notes.

Approve a tool call

When the tool-approval modal is up, ↵ allows the call once and ⌘A always allows it for the rest of the session.

Deny a tool call

Esc denies the pending tool call. The model sees a tool error and decides what to do next.

Stop a turn

Click Stop in the title bar to cancel any in-flight turn. Streams stop, the partial turn rolls back, and context stays clean.

// 09 shared state

Shared state with the CLI

Both surfaces read and write the same files under ~/.aictl/. There is no sync layer — they are two views of the same on-disk state.

config

~/.aictl/config — provider, model, security policy, redaction rules, every AICTL_* knob. Edited from either surface, reread on next launch by both.

sessions

~/.aictl/sessions/ — one JSON file per session. The desktop and the CLI list the same set; a session you started here resumes from the terminal and vice versa.

agents & skills

~/.aictl/agents/ and ~/.aictl/skills/ — the same catalogues the CLI exposes through /agent and /skills. Project-local overrides under .aictl/agents/ work in both surfaces.

keys

API keys go through the same keyring path. Lock from the CLI, unlock from the desktop — the keychain entry is the same. On macOS, each signed binary has its own Keychain ACL, so the first cross-binary read of a key prompts for your login password — click Always Allow to skip future prompts for that key/binary pair.

mcp · hooks · plugins

mcp.json, hooks.json, and plugins/ all light up in both surfaces. Configure once.

audit & stats

~/.aictl/audit/ and ~/.aictl/stats aggregate across both surfaces. Daily and monthly token usage rolls up tool calls from desktop sessions and CLI sessions together.

// 10 security

Security policy

The same security policy the CLI ships. On by default, tunable from Settings, never bypassed silently.

CWD jail

Tools run jailed inside the workspace. File reads and writes outside the workspace are rejected. Switch the workspace and the jail moves with it.

Shell allowlist

exec_shell goes through the same allow / block lists the CLI uses. No subshell, no compound commands, no hidden flag escapes.

Environment scrub

Tool subprocesses launch with a scrubbed environment — no AICTL_* secrets leak into spawned processes by accident.

Injection guard

Outbound prompts pass through the prompt-injection guard before they hit a provider. Suspicious payloads can be blocked, redacted, or just flagged depending on policy.

Redaction

Three-layer redactor (regex, entropy, optional NER) at the network boundary. Anything matching a credential or PII pattern becomes a placeholder before the request leaves the machine.

Audit log

Every tool call lands in ~/.aictl/audit/<session-id> as JSONL. Replay any session, in any surface, after the fact.

// 11 updates

Updates & uninstall

The app checks for updates on launch and hands them to you with a one-click install. Removing it is a single drag.

Auto-update

Updates download from GitHub Releases and install in place after a minisign signature check — independent of Apple's Developer ID codesign. No App Store, no third-party updater.

Manual check

Settings → About → Check for updates triggers the same flow on demand.

Uninstall

Drag aictl.app from /Applications to the Trash. Your config, agents, sessions, and keys under ~/.aictl/ are left intact — the CLI keeps working.

Wipe state

To remove everything — config, keys, agents, sessions, audit log — delete ~/.aictl/ manually: rm -rf ~/.aictl.
